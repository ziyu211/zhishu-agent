## 2. 已报缺陷：对话提示保存成功，技能页看不到 —— 根因与修复

### 2.1 现象与链路

用户在对话中要求「保存为技能」→ 对话回复"已保存成功" → 打开「技能」页面找不到该技能。

完整链路核查：`create_skill 工具(toolset=skills)` → `data/skills/<name>/module.json(+SKILL.md)` → `GET /api/v1/skills`（`_list_modules`，按 shared+本人+admin 过滤）→ 前端 SkillsView 原样渲染。**前端无隐藏过滤，列表 API 与落盘路径一致。**

### 2.2 根因（三层）

1. **工具误选**：模型把「保存技能」误用为 `create_tool`（注册的是会话内临时 `dyn_` 动态工具：进程重启即清空、**不会**进入 `data/skills/`、技能页不可见），却照常回复"已保存成功"。
2. **谎报成功**：模型未真正调用任何落盘工具、或 create_skill 报错后，仍向用户宣称保存成功。
3. **中文名促成因素**：`create_skill`/`sanitize_name` 只允许 ASCII，用户以中文命名（如「写周报」）时名称被滤空 → 报「名称非法」→ 模型改道 create_tool 或谎报。

### 2.3 修复（三层服务端硬护栏，不依赖模型自觉）

| # | 层 | 修复 | 文件 |
|---|---|---|---|
| 1 | **工具调用拦截** | `create_tool` 检测到技能保存意图（名/描述含「技能/skill」+保存语义）→ 硬性返回错误并强制改道 `create_skill`，从源头杜绝错误落盘路径 | `code_exec.py` |
| 2 | **回合后校验** | agent 循环收尾：用户消息命中「保存/创建技能」意图（中英文正则）且本回合轨迹无成功 `create_skill`（返回含「已持久化」）→ 最终回复尾部**如实纠正**（"未检测到技能成功写入技能库…"），假成功不再可能到达用户 | `agent.py` |
| 3 | **名称与落盘一致性** | ① `sanitize_name`/`_sanitize` 允许中文（无路径穿越风险）；② `create_skill` 工具与 API 层 `write_meta` 口径统一，同时写 `SKILL.md`（Hermes 互通）；③ 系统提示强化"收到『已持久化』才可宣称成功" | `runtime.py` / `skills.py` / `system_prompt.py` |

### 2.4 验证

- 单测 `test_skill_save_guard.py`：**44/44**（意图识别 16 例、落盘判定 5 例、纠正追加 4 例、拦截 5 例、中文名 4 例、真实落盘 8 例、用法统计 4 例）
- 真实 HTTP 冒烟（对运行实例）：中文技能创建 → 列表可见 → 清理 **9/9**（§5.4）

## 9. v1.0.44 补充修复：SVIPFTP 技能假成功漏网路径

> 来源：离线内网同版本机器真实复现——用户要求「创建 SVIPFTP 技能」，模型 `code_exec` 因三引号嵌套 `SyntaxError` 失败，改用 `file_write`+`create_skill` 两步法后，**谎称「✅ 创建完成 SVIPFTP 技能已成功创建」，但技能页看不到**。

### 9.1 根因（v1.0.43 护栏两处缺口）

| 缺口 | 说明 | 后果 |
|---|---|---|
| **意图正则过窄** | `(.{0,6}技能)` 仅允许动词↔「技能」间 0–6 字符；「创建 **SVIPFTP** 技能」中间夹技能名共 9 字符 >6 → 正则不命中 | 护栏根本没触发 |
| **只查用户意图、不查模型自报成功** | 护栏仅在「用户要求保存」时生效；本案例是**模型自己在回复里断言成功**，且从未真正发出 `create_skill` 工具调用 | 假成功直达用户 |

本质：技能页只读取 `data/skills/*/module.json`；模型只 `file_write` 了 `svipftp.md` 媒体文件（非技能库），从未写入技能库，故技能页永远看不到。

### 9.2 修复（服务端双路护栏，不依赖模型自觉）

1. **`agent.py` 意图正则放宽 `.{0,6}` → `.{0,40}`**：覆盖「创建 SVIPFTP 技能」这类技能名嵌入动词与名词之间的真实语序。
2. **新增 `_skill_success_claimed` 检测模型自报成功**：识别「创建完成 / 已成功创建 / 保存成功 / 已保存为技能」等断言；并**排除误报**——回复含真实工具返回的「已持久化」、或引用历史技能（之前/上次创建的）时不纠错。
